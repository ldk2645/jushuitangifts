# 荣耀礼赠登记工作台 · 详细使用说明

- 版本：`v1.3.0-ry.1`（荣耀独立版，Git 分支 `honor`）
- 更新：2026-11-05
- 适用目录：`gifts-ry`（桌面版端口 **8767**；便携版端口 **8766**）
- 代码仓库：<https://github.com/ldk2645/jushuitangifts/tree/honor>

> 本文面向实际操作人员（主机操作者）。它只适用于荣耀独立版：只登记**原地址**礼赠、只使用班牛“聚水谭赠品补发—荣耀”工作表、只处理**荣耀**品牌礼品。原项目（融合版，端口 8765）的配置、数据和端口与本版隔离，不要混用。
>
> 本版本不会自动重试失败订单；提交结果不确定时禁止再次提交，必须人工核查。截至本说明更新时，真实平台整单验收只完成过一单（见 [发布说明](releases/v1.3.0-ry.1.md)），其余为隔离测试。不要把“代码已修复”理解为“线上所有场景已验证”。

## 1. 快速开始（五分钟）

1. 把整个 `gifts-ry` 目录放在本机固定位置（**不要**放在受 Windows 沙箱限制、会自动打低完整性标签的目录）。
2. 首次使用：右键 `setup.ps1` →“使用 PowerShell 运行”，或在本目录执行：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   它会创建 `.venv` 并安装 `requirements.txt` 中的依赖（Selenium 等）。需要 Python 3.11+；目标电脑需能访问聚水潭和班牛。
3. 双击 `login.bat` 打开平台登录助手，分别完成聚水潭、班牛登录和验证码，点“我已登录，确认并保存”，再关闭助手窗口。
4. 双击 `start.bat` 打开工作台（本机 <http://127.0.0.1:8767/>）。
5. 在表格里填写订单号、选择礼品，点“开始登记”；登记中不要重复点击、不要关闭工作台。
6. 结束工作时双击 `stop.bat`，等待“已关闭”提示后再关闭电脑或重启。

> 如果浏览器启动失败、登录助手只打开一个平台窗口、或提示完整性级别问题，先看第 11 节和第 14 节常见问题。

## 2. 目录、配置与数据

### 2.1 根目录入口

| 文件 | 用途 |
| --- | --- |
| `start.bat` | 启动工作台（本机 8767），自动打开浏览器 |
| `login.bat` | 打开平台登录助手（聚水潭 + 班牛），用于登录、验证码、保存会话 |
| `stop.bat` | 正常关闭工作台：先停止接收，再等待在途任务、关闭业务浏览器、释放队列锁 |
| `update-gifts.bat` | 按 `config/gifts-*.txt` 只读查询班牛商品名称并更新礼品目录（详见第 5 节） |
| `verify-honor.bat` | 只读检查班牛登录、荣耀工作表与空白表单，报告 `.tmp/honor-page-structure.json`；不提交 |
| `browser-settings.bat` | 设置两个业务浏览器是否无头运行（验证码/登录时建议显示窗口） |
| `diagnose-login.bat` | 只读诊断两个平台的登录窗口/配置锁/会话，报告 `.tmp/login-diagnostic.json` |
| `diagnose-selenium.bat` | 只读检查 Chrome/Edge 能否启动，报告 `.tmp/browser-startup-result.json` |
| `fix-browser-integrity.bat` | 修复项目目录被写入低完整性级别标签的问题（不修改文件内容） |
| `lan-info.bat` / `update-lan.bat` | 局域网共享信息查看 / 网络变化后的配置与防火墙更新（见第 12 节） |
| `setup.ps1` | 首次安装 Python 虚拟环境与依赖 |

### 2.2 `config/`（配置，属于本机数据）

| 文件 | 说明 | 是否上传 Git |
| --- | --- | --- |
| `gifts.json` | 礼品目录：编码、名称、别名 | 是（不含账号信息） |
| `gift_groups.local.json` | 本机礼品分组与归属 | **否**（`.gitignore` 排除） |
| `gifts-荣耀.txt` | `update-gifts.bat` 的输入示例/增量编码清单，不是目录全集 | 是 |
| `accounts.local.json` | 账号密码（DPAPI 加密）与业务浏览器无头选项 | **绝对不要上传** |
| `network.local.json` | 局域网 IP/子网/域名配置（启用后生成） | **否** |

> 账号密码、Cookie、加密会话、日志和业务数据都不得提交到 GitHub。仓库 `.gitignore` 已排除 `config/accounts*.local.json*`、`config/*.local.json*`、`data/`、`.tmp/`、`*.dpapi`、`logs/`、`.venv/` 等。

### 2.3 `data/`（业务数据，必须备份，不要手工编辑）

| 路径 | 内容 |
| --- | --- |
| `registrations.json` | 当前草稿表格（订单号、礼品编码、数量、选择依据）；由工作台自动保存 |
| `registration_jobs/` | 每批登记任务的持久化快照、状态、事件、防重依据、`.queue-pause.state`（共享环境暂停记录） |
| `registration_jobs/execution_history/` | 失败/成功执行历史（用于失败清单、重登防重） |
| `registration_jobs/auto_reviews/` | 延迟只读复核队列（180 秒后一次） |
| `draft_archive/` | 主机删除/归档草稿前的备份 |
| `manual_status.json` | 主机人工状态标记与审计 |
| `sessions/` | 平台加密会话快照（DPAPI，仅当前 Windows 用户可解密） |
| `browser/`、`browser_edge/` | 两个平台的独立浏览器配置目录（可能较大，不必备份） |
| `exports/` | 每日归档导出（后台维护任务生成） |
| `maintenance.json` | 后台维护任务状态 |
| `frontend_access.log` | 工作台访问日志（排错用，含网段，不含密码/请求体） |
| `server.pid` | 运行中工作台进程号（正常关闭会删除） |

**备份建议**：关闭工作台和登录助手后，复制 `config/gifts.json`、`config/gift_groups.local.json`、`config/accounts.local.json`（如果换了 Windows 用户则不要复用）、整个 `data/`（至少 `registrations.json`、`registration_jobs/`、`execution_history/`、`manual_status.json`、`sessions/`）。**不要**在恢复时删除 `execution_history/` 或手工修改任务 JSON，否则会破坏防重与历史证据。

## 3. 账号与登录

### 3.1 当前荣耀账号

- 班牛：使用用户提供的荣耀账号（尾号 0845），登录入口 <https://work.bytenew.com/>，登录后先进入“赠品补发看板——荣耀”，程序确认后再进入“聚水谭赠品补发—荣耀”工作表。
- 聚水潭：使用原项目的账号/加密会话在本目录的独立副本；不会读取或改写原项目数据。
- 荣耀登记工作表固定为 <https://work.bytenew.com/app.html#/applet/appNew/projectNew/58231/27715>。不要把班牛登录首页与登记工作表混为一谈。

### 3.2 手动登录流程（推荐）

1. 先双击 `stop.bat` 关闭工作台（避免业务浏览器与登录助手争用同一浏览器配置）。
2. 双击 `login.bat`，会显示两个平台窗口。
3. 在窗口内手动登录，完成验证码/扫码/二次验证。
4. 每个平台完成且页面进入正常业务界面后，在登录助手中点“我已登录，确认并保存”。
5. 关闭登录助手窗口；再双击 `start.bat` 启动工作台。

登录助手保存的是加密会话，不会保存明文密码。换电脑或换 Windows 用户后，旧 `data/sessions/*.dpapi` 无法解密，重新手动登录保存即可。

### 3.3 自动登录（可选）

如果本机 `config/accounts.local.json` 已保存 DPAPI 加密账号密码，登录助手/业务浏览器在会话过期时会**最多尝试一次**自动登录；失败、超时或需要验证码会锁存，必须人工处理，不会反复发送密码。没有账号配置时完全不影响手动登录使用。

- 桌面版的 `tools/setup_honor_accounts.py` 仅用于“从原项目目录迁移”的本机场景（从上一级原项目复制聚水潭加密账号，并交互录入班牛账号）；新电脑/新用户请直接用 `login.bat` 手动登录并保存会话。便携版使用 `settings.bat` 填写两平台账号。账号文件格式见 `docs/portable-settings.md`。
- 不要手工编辑 `password_dpapi`，也不要把 `accounts.local.json` 发给他人。
- 自动登录不是登记成功的依据；登记成功始终以班牛任务和聚水潭新增记录核验为准。

### 3.4 验证码与登录助手

验证码、扫码、短信验证必须由人工完成。`login.bat` 始终显示窗口；业务浏览器可设置无头，但遇到验证码时建议先关工作台、用 `login.bat` 完成登录保存，再启动工作台。登录失败不会自动重试业务登记。

## 4. 工作台基本操作

### 4.1 界面概览

- 顶部：品牌、`平台登录` 按钮（仅主机，打开登录助手）。
- 工具栏：新增行、删除行、撤销、复制区域、粘贴区域、新增礼赠、自动列宽、礼品分组筛选、重新登记、修改所选状态、取消所选排队、保存、开始登记。
- “概况与管理”（可展开）：登记统计、流程说明、主机管理（礼品分组管理、导出今日日志、删除所选/全部、维护状态）。
- 表格列：**订单号（A）、礼品（B）、状态（C）**。状态列由后端结果更新，不能手工填写或填充。
- 底部：添加一行、快捷键提示、状态统计与“暂停待恢复”数量。

### 4.2 填写订单和礼品

- 订单号：完整电商订单号，保留前导零；不要带空格。
- 礼品：点击礼品单元格 → 选择器里搜索/勾选礼品；也可直接输入名称/别名/编码并回车。
  - 编码必须**完整精确**匹配（区分大小写、标点、前导零）；名称和别名用于搜索，同名不同编码会保留歧义，需要选具体编码。
  - 同一礼品可登记多件：勾选后点选项旁的 **− ×N ＋** 调整（1–99 件）；表格显示“名称 ×N”。
  - 纯文本输入重复同一礼品（如“收纳包、收纳包”）会按 2 件保存；超过 99 件会提示并拒绝整次应用。
- 一行可以包含多个礼品；同一订单的全部礼品会进入**同一个班牛工单**（不是每件一个工单）。
- 改地址：本版本不支持。旧草稿中 `change_address=true` 的行会显示“旧草稿不支持”，请核对原意后删除并新建原地址订单。

### 4.3 表格快捷操作

| 操作 | 方式 |
| --- | --- |
| 选中单元格/区域 | 鼠标拖选、Shift+方向键；Ctrl+A 全选数据区域 |
| 编辑 | 双击单元格、F2、直接输入 |
| 提交编辑 | Enter / Tab / 点击其它单元格 |
| 下一行/上一行 | Enter / Shift+Enter（编辑完成时） |
| 撤销 | Ctrl+Z（最多 50 步；只恢复草稿，不恢复后端任务） |
| 复制 | Ctrl+C 或“复制区域”；内部结构化剪贴板会保留编码和数量 |
| 粘贴 | Ctrl+V 或“粘贴区域”；支持 Excel 多行多列 |
| 向下填充 | Ctrl+D、拖动右下角填充柄、双击填充柄 |
| 新增行 | 工具栏“添加”（可输入 1–10000 行）或底部“添加一行” |
| 删除行 | 选中行后“删除行” |
| 列宽/全屏 | “自动列宽”；“全屏表格” |

**复制/粘贴数量限制**：同一礼品多件只有在本工作台内部的结构化复制/粘贴、向下填充时才完整保留数量；复制到 Excel/纯文本会按每种 1 件（界面已提示）。纯文本里的“×2”不会被静默当成名称或数量。

### 4.4 自动保存与冲突

- 编辑后约 0.65 秒自动保存；也可点“保存”。保存状态显示在表格标题右侧。
- 多窗口/多设备编辑同一草稿时，较旧版本保存会冲突，不会覆盖新数据：先复制自己的编辑内容，再刷新页面后重填。
- 后台维护或其他窗口更新草稿时，页面会提示；不要在未保存内容很多时直接刷新。
- 连接中断时保留页面最后状态，不会自动补发保存或登记请求；恢复后先核对最新状态再操作。

## 5. 礼品目录更新（`update-gifts.bat`）

### 5.1 输入格式

- 每个分组一个 UTF-8 文本文件：`config/gifts-<分组名>.txt`，每行一个完整商品编码。
- 空行忽略；重复编码按首次出现去重；保留大小写、前导零和标点。
- 当前仓库的 `config/gifts-荣耀.txt` 是示例/增量清单（约 191 个编码），**不是**目录全集；当前目录约 193 项，以工作台实时显示为准。

### 5.2 规则

1. 只用**班牛**查询，不要求聚水潭名称一致（当前业务约定）。
2. 每个编码只读搜索，以班牛商品列表**第一行**的商品名称作为目录名称；同一编码有多条重复记录时不翻页。
3. 改名：新名称写入 `gifts.json`，旧名称自动保留为别名。
4. 已有编码查不到名称：保留原名，只更新该编码的分组；不会删除礼品。
5. 新编码查不到名称：**阻止整批写入**（报告 pending），需要人工核实编码/班牛目录后重试。
6. 未在 TXT 中出现的礼品和分组保持不变；不会把目录裁成 TXT 的长度。

### 5.3 操作流程

1. 双击 `update-gifts.bat`（内部执行 `tools/update_gifts.py --interactive`）。浏览器会打开班牛空白新建表单，只读查询，不加入礼品、不输入订单、不提交工单。
2. 如果班牛未登录/会话过期：程序在可见窗口中提示，默认最多等待 **300 秒**供人工登录/验证码；登录成功后自动保存加密会话并继续核实。`--headless` 表示不等待（请先用 `login.bat` 登录）。
3. 预览会打印新增、改名、分组变化、名称待核实、阻止项（按原因合并显示）；确认无误后输入 **Y** 才写入。
4. 写入前有备份、计划/原文件摘要和失败回滚；报告在 `.tmp/catalog-maintenance/reports/`。
5. 可选参数：
   - `update-gifts.bat --login-wait 600`：等待登录 600 秒；
   - `update-gifts.bat --offline`：不联网，仅按已有目录补充分组；
   - `update-gifts.bat --headless`：隐藏浏览器（需先登录）。
6. 更新完成后刷新工作台页面即可看到新目录；如果更新期间营业，建议等当前登记任务结束后再操作。

### 5.4 常见结果

| 预览文字 | 含义 | 处理 |
| --- | --- | --- |
| “配置已是最新，无需写入” | 名称/分组无变化 | 无需操作 |
| “名称待核实（保留原名，仅更新分组）” | 已有编码在班牛未取到名称 | 确认编码正确、班牛目录有该商品；保留原名不影响登记 |
| “阻止应用（新编码无名称不新增）” | 新编码未取得名称 | 核实编码/班牛登录后重试；整批不会写入 |
| 等待登录超时 | 班牛会话无效 | 先 `login.bat` 手动登录，再重试或加 `--login-wait` |

## 6. 开始登记（核心流程）

### 6.1 开始前检查

- 草稿至少一行有**完整订单号**和**有效礼品**（编码在目录中且已确认）。
- 平台已登录；主机没有在途登记任务；工作台没有显示红色“登记已暂停”横幅。
- 当前工作台是主机 `http://127.0.0.1:8767/`（远端设备不能执行开始登记、重登、主机恢复等主机管理操作）。

### 6.2 点击“开始登记”后发生什么

1. 工作台保存草稿 → 后端创建持久化任务（同一订单+同一组编码+数量组合已有任务时复用，不重复执行）。
2. 聚水潭只读查询原订单，确认订单存在并取得登记前礼品基线。
3. 班牛打开“聚水潭赠品补发—荣耀”空白表单：选择补发类型、输入订单号并拉单、校验公司=能良移动/品牌=荣耀、问题类型=赠品补发、加入全部礼品、按件数填写“数量”列、金额保持 0、核对全部字段。
4. 提交前再次查询该订单已有班牛任务作为基线，然后**只点击一次提交**。
5. 读取班牛回执：工单编号、创建时间、同步状态、回传聚水潭售后单内部单号。
6. 回到聚水潭只读复查：确认新增记录包含本次全部编码和数量合计、且不是旧记录。
7. 返回成功/失败到状态列；失败不会自动重试。

### 6.3 成功、失败与“不确定”

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 成功 | 回执与聚水潭新增记录都核对通过 | 无需操作；可在“导出今日日志”查看记录 |
| 失败 | 明确业务失败或明确未提交 | 查看详情；符合条件可用主机“重新登记” |
| 失败（提交结果不确定） | 已点击提交但未取得可核对回执 | **禁止再次提交**；先人工核对班牛/聚水潭，必要时用“修改所选状态”登记人工结论 |
| 暂停待恢复 | 共享环境故障，尚未执行的后续订单 | 等待主机处理并点“主机恢复”（见第 8 节） |

### 6.4 防重规则

- 任务身份 = 订单号 + 整组编码（+ 非默认数量）；同组合再次开始会复用旧任务，不会重复提交。
- 已提交过（即使失败/不确定）的订单，禁止自动重复登记。
- “重新登记”只对**明确未提交**的失败任务开放，并且会重新执行安全核查（订单、旧任务、编码/数量）；提交不确定、同编码不同数量等情况会阻止或要求人工核查。
- 不要为了让失败“变绿”而重复点开始、手工改状态或删除任务历史。

### 6.5 登记中可做/不可做

- 可以做：查看状态、编辑其它草稿行、保存、准备下一批订单（排队串行执行）。
- 不要做：重复点“开始登记”、关闭工作台/浏览器、手工操作业务浏览器表单、登录助手与工作台同时占用同一平台浏览器。
- 暂停期间：工作台可查看、可取消未执行项、可正常关闭；不要强行刷新页面期望自动恢复。

## 7. 失败清单、重登与人工状态

### 7.1 失败清单与重新登记

- 主机点工具栏“重新登记”打开失败清单；只有“可重登”的失败项能提交重登。
- 可重登通常要求：自动登记失败且**明确未提交**（`not_submitted`），没有提交尝试或历史证据冲突。
- 不能重登：提交结果不确定（`uncertain`）、已有提交尝试、已成功、人工标记冲突、同编码不同数量的旧任务等。
- 重登会：重新查询订单、核查班牛旧任务和基线、按当前目录名称重新登记；失败的任务历史原样保留，不会覆盖。
- 重登同样受暂停状态控制：暂停期间不能重登。

### 7.2 人工状态标记

- 主机选中行 → “修改所选状态”：成功 / 失败 / 人工待核查 / 恢复自动显示。
- 用途：人工核对平台后记录结论；人工成功会持续保留并排除自动重登，但**不能**替代“新增记录核验成功”，也不计入自动成功导出。
- 人工标记绑定行签名；后台时间变化不会撤销，除非主机明确修改或恢复自动显示。人工结论会写入审计。

### 7.3 取消排队

- 主机选中行 → “取消所选排队”（或状态列上的“取消”）。
- 只取消尚未开始执行的任务（`queued` 或暂停中的 `waiting`）；已开始/已提交的订单不能取消。
- 取消会记录主机取消依据，不伪装成失败/成功，保留原任务历史；重启或刷新不会自动恢复执行。

## 8. 共享环境暂停与主机恢复

### 8.1 什么时候会暂停

出现以下共享环境问题时，当前订单按真实边界结束，**本批次后续未执行订单**转为“暂停待恢复”：

- 平台登录失效、需要验证码/扫码等人工介入；
- 业务浏览器被关闭、驱动连接不可用；
- 班牛已有归属不明/被人工修改的遗留表单，无法安全确认；
- 提交已点击但结果不确定（此时当前订单为“失败/不确定”，后续暂停）；
- 可恢复页面故障自动恢复一次失败（升级为人工暂停）。

### 8.2 暂停时界面会显示

- 顶部黄色横幅：“登记已暂停，后续未执行订单未提交”，包含原因、平台、阶段、等待数量、恢复条件。
- 当前失败行：显示失败详情；后续未执行行：显示“暂停待恢复”（不是失败），状态列旁有“取消”可取消该行。
- “开始登记”按钮禁用；普通刷新/健康轮询不会自动恢复或重提。

### 8.3 主机恢复步骤

1. 在主机处理原因：完成平台登录/验证码、关闭或处理遗留表单、恢复浏览器网络；必要时先 `stop.bat` 关闭工作台，用 `login.bat` 登录保存。
2. 回到工作台（主机 `127.0.0.1:8767`），点击暂停横幅上的 **“主机恢复”**。
3. 程序会先只读验证聚水潭订单页和班牛礼赠列表是否就绪：
   - 未就绪：返回 409，横幅保持，显示原因；处理后再试；
   - 就绪：清除暂停，把“暂停待恢复”行重新排队，各执行一次。
4. 原失败/不确定订单不会重放；如需处理，走第 7 节失败清单/人工核查。

### 8.4 暂停期间关闭/重启

- 暂停时等待队列已安全排空，可正常双击 `stop.bat` 关闭；关闭不会挂起。
- 重启后仍保持暂停状态和未执行行；不会自动恢复或重复提交。
- 可先取消部分未执行行，再恢复其余行。

## 10. 关闭与重启

1. 确认没有正在登记的订单（状态列为“正在登记/查询订单/复查确认”时先等待）。
2. 双击 `stop.bat`，等待命令窗口提示关闭完成；它会先停止接收新任务，再等待在途任务、关闭业务浏览器、释放队列锁和端口。
3. 关闭工作台不会删除草稿、任务历史、人工标记或会话快照。
4. 重新启动用 `start.bat`；浏览器页面如仍打开，刷新即可。升级代码后必须重启工作台，后端修复才会生效。

不要用任务管理器结束正在提交的进程；不要按进程名批量结束所有 Chrome/Edge（只处理本工具可证明归属的窗口/进程）。

## 11. 平台登录与浏览器排错

### 11.1 平台登录只打开一个平台浏览器

先看登录助手该平台行文字和 `data/status.json` 中该平台 `state/warning`：

- 显示“浏览器启动未完成（SessionNotCreatedException/WebDriverException）”或停在“正在启动浏览器”：通常是该平台浏览器配置被另一本工具浏览器/后台进程占用（另一个平台空闲，所以能打开）。
  1. 先 `stop.bat` 关闭工作台和业务浏览器；任务管理器结束命令行含 `data\browser\banniu`（便携版 `data\browser_edge\banniu`）的 chrome.exe/msedge.exe 和多余助手进程。
  2. 双击 `diagnose-login.bat` 只读诊断，报告 `.tmp/login-diagnostic.json`。
  3. 若仍无法启动：关闭所有本工具窗口，把 `data\browser\banniu`（或 `data\browser_edge\banniu`）改名为 `.bak`，再运行 `login.bat` 重建配置并手动登录。
- 显示“等待你手动登录”或页面已打开：先用 Alt+Tab 找班牛窗口（可能被聚水潭挡住），完成登录/验证码后点“我已登录，确认并保存”。
- 提示“登录配置正在使用”：先关闭占用配置的工作台/登录助手再试。
- 换了电脑/Windows 用户：旧 `data/sessions/*.dpapi` 和账号密文无法解密，重新手动登录保存；需要自动登录时在目标电脑重新保存账号。

### 11.2 业务浏览器无法启动

- 双击 `diagnose-selenium.bat`：独立空白页检查 Chrome/Edge 有头/无头启动，报告 `.tmp/browser-startup-result.json`，不读取账号/业务数据。
- 若报告 `SessionNotCreatedException`、`tab crashed` 或完整性级别 `low`：双击 `fix-browser-integrity.bat` 修复低完整性标签，再复查。
  - 原因通常是项目目录被 Windows 沙箱/权限工具写入低完整性标签，浏览器无法创建窗口/临时文件；不是代码或账号问题。
  - 修复只调整完整性标签，不修改文件内容；之后如需在受限沙箱运行本工具，请改用完全权限。
- 驱动下载失败：检查网络/代理后重启浏览器；缓存位于 `data/selenium`。不要删除任务记录或重复提交订单。

### 11.3 登录助手与业务浏览器不能同时占用同一平台配置

同一平台的浏览器配置同一时间只能被一个本工具进程使用。正确顺序：关闭工作台 → 登录助手登录保存 → 关闭助手 → 启动工作台。

## 12. 局域网共享（可选，默认关闭）

默认只允许本机访问。需要其他设备使用工作台时：

1. 在路由器为主机保留固定内网 IP。
2. 主机运行（示例）：
   ```powershell
   .\.venv\Scripts\python.exe main.py --enable-lan --lan-ip 192.168.1.100 --lan-subnet 192.168.1.0/24
   ```
   可选 `--domain gifts.example.com`（内网 DNS/Cloudflare 仅 DNS 解析到内网 IP；不要做公网端口映射）。
3. 双击 `update-lan.bat` 检测当前网卡并更新配置与防火墙（需要管理员授权）；网络/IP 变化后重跑。
4. 双击 `lan-info.bat` 查看共享地址、用户名 `gift` 和六位访问密码（密码用 DPAPI 加密保存在 `data/lan_access.dpapi`）。
5. 其他设备打开 `http://<主机内网IP>:8767/`，输入 `gift` + 密码；主机本机 `127.0.0.1:8767` 免登录。
6. 关闭共享：`main.py --disable-lan`，并可用 `allow-lan.ps1 -Port 8767 -Disable` 撤销防火墙规则；重启后生效。

限制与注意：

- 平台登录、验证码、失败重登、人工状态、导出、删除、暂停恢复等主机管理只允许在主机回环地址操作；远端页面按钮会禁用。
- 其他设备只能编辑草稿和查看状态；所有人共享同一草稿/任务队列/防重记录。
- 当前为 HTTP（仅可信内网），不是 HTTPS；不要暴露到公网。
- 网络/IP 变化会提示，需要人工核对并更新 Cloudflare/配置/防火墙；详见 [局域网使用说明](lan.md)、[便携版局域网说明](portable-lan.md)。
- 排错看 `data/frontend_access.log`：403=Host/子网不匹配，401=缺访问密码，无新行=请求未到达。不要上传该日志。

便携版（U 盘/独立运行时）使用端口 **8766**，入口为 `lan-setup.bat`/`lan-info.bat`/`lan-disable.bat`，账号用 `settings.bat`/`accounts.bat`；详见 `docs/portable-lan.md`、`docs/portable-settings.md`。桌面版请勿混用便携版脚本。

## 13. 数据安全、备份与升级

### 13.1 不要上传/外发的文件

- `config/accounts.local.json`（账号密码密文）、`config/network.local.json`、`config/gift_groups.local.json`
- `data/`（草稿、任务历史、执行历史、人工标记、会话、浏览器配置、日志、导出）
- `.tmp/`（诊断报告、目录维护报告、截图）
- `*.dpapi`、`*.log`、`.venv/`

GitHub 仓库只包含代码、文档、`config/gifts.json` 目录和示例 TXT。提交前已确认 `.gitignore` 生效；如新增敏感文件，先检查 `git status`，不要 `git add -f`。

### 13.2 备份与恢复

- 备份：关闭工作台/登录助手后复制 `config/`（至少 gifts.json、gift_groups.local.json、accounts.local.json）和 `data/`（建议整目录）。
- 恢复：先关闭工作台 → 替换/恢复对应文件 → 启动 → 刷新页面；不要删除 `execution_history/`、`registration_jobs/` 中的任务，否则防重和历史证据丢失。
- 浏览器配置目录（`data/browser*`）可选备份；换电脑通常重建更干净。

### 13.3 升级/回滚

1. 确认没有在途任务，记录当前版本；备份 `config/` 与 `data/`。
2. 正常关闭工作台和登录助手。
3. 获取新代码（GitHub `honor` 分支或新压缩包），保留本机 `config/`、`data/`、`.venv` 可按需重建。
4. 必要时运行 `setup.ps1` 更新依赖；启动 `start.bat`，刷新页面。
5. 升级不会自动重新派发已有任务；历史防重依据保留。
6. 回滚同理：保留 `data/`，换回旧代码启动；若旧代码不认识新状态，先备份再操作，不要手工改任务 JSON。

## 14. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 打不开 http://127.0.0.1:8767/ | 工作台未启动/端口被占 | 双击 `start.bat`；`start.bat` 报错看窗口；`stop.bat` 后重试，或查 `data/server.pid` 对应进程 |
| 页面显示“与主机的连接暂时中断” | 服务重启/网络/浏览器休眠 | 保留页面；恢复后先核对状态；不会自动重发保存或登记 |
| 开始登记按钮灰/提示暂停 | 工作台处于暂停 | 处理登录/验证码/遗留表单后点“主机恢复”（第 8 节） |
| 提示“请先完善第 N 行” | 订单号/礼品缺失或未确认 | 补全订单号、重新选择有效礼品 |
| 开始后提示“已有相同任务/复用” | 防重命中 | 正常现象；查看该行状态，不要重复点 |
| 状态“失败” | 平台明确失败/未提交 | 看详情；符合条件用“重新登记”，否则人工核查 |
| 状态“失败（结果不确定）” | 已点击提交但回执不确定 | 禁止重提；人工核对班牛/聚水潭，必要时人工标记 |
| 状态“暂停待恢复” | 共享环境暂停 | 主机处理并恢复（第 8 节）；不要当失败重提 |
| 多个窗口保存冲突 | 另一窗口/设备先保存 | 复制自己的内容→刷新→重填；不要强行覆盖 |
| 停止工作台卡住 | 有在途任务/浏览器关闭慢 | 等待完成；不要强杀提交中的进程；必要时 `diagnose-login.bat` 查配置占用 |
| 只打开一个平台浏览器 | 该平台配置被占用 | 见 11.1；`diagnose-login.bat` |
| 浏览器启动失败/低完整性 | 沙箱写入了低完整性标签 | `diagnose-selenium.bat` + `fix-browser-integrity.bat`（11.2） |
| 登录总是失败/要验证码 | 密码变更、二次验证、会话过期 | 手动 `login.bat` 完成验证码并保存；不要反复自动登录 |
| 目录更新显示“阻止应用” | 新编码未取得班牛名称 | 核对编码和班牛目录；登录后重试；不会写入半批 |
| 复制到 Excel 后数量变成 1 件 | 纯文本/Excel 不编码数量 | 设计限制；在工作台内结构化复制/粘贴或重新在 Excel 后手动选择数量 |
| 导出/维护报错 | 磁盘/权限/备份失败 | 看“维护状态”和 `.tmp` 报告；先备份 `data/` 再排查 |
| 换电脑后自动登录失效 | DPAPI 绑定原 Windows 用户 | 重新手动登录保存；需要自动登录就在新机重新保存账号 |

## 15. 当前限制与未验证事项

- 只支持**原地址礼赠**；改地址请求会被拒绝。
- 每单全部礼品一个班牛工单，单项金额 0；同单重复开始不会重复提交。
- 自动重试关闭；失败/不确定必须人工核查，重登仅限明确未提交的失败。
- 纯文本/Excel 复制粘贴不保留多件数量（界面已提示）；跨 Excel 保留数量需另行设计格式。
- 真实平台验收有限：仅在 2026-11-05 完成过一单真实登记（见发布说明）；登录/验证码恢复、浏览器断连、HTTP 拒绝时序、数量列等仍以隔离测试和受控实验为主，不能宣称所有线上场景已验证。
- 诊断脚本/文档中对 `SessionNotCreatedException` 的解释需结合完整性、配置占用、驱动版本分渠道判断，不能单凭异常名断定原因。
- 本仓库文档中较早版本的实单记录属于原项目历史，不是荣耀版验证。
