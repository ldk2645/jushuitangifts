# 局域网共享工作台

主机继续运行 Python 和 Selenium，其他设备只需浏览器。同一主机上的各设备共用礼品清单、草稿、串行队列和持久化防重记录。登记仍需明确点击开始，每项业务最多提交一次。

## 配置主机

先在路由器中为主机保留局域网 IP。以下地址和域名仅为示例，应替换为实际配置：

```powershell
.\.venv\Scripts\python.exe main.py --enable-lan --lan-ip 192.168.1.100 --lan-subnet 192.168.1.0/24 --domain gifts.example.com
```

配置保存在 `config/network.local.json`。独立访问密码自动生成六位数字，保留可能的前导零，并使用当前 Windows 用户的 DPAPI 加密到 `data/lan_access.dpapi`；不使用聚水潭或班牛的密码，不把密码放进网址、网页配置或日志。两份本机文件均不进入 Git。

旧版长密码在普通启动时保留。如果需要换成六位数字，运行以下命令后正常重启工作台；已经是六位数字时不会再次更换。其它设备需改用新密码，浏览器若保留旧凭据可关闭对应标签页后重新打开。

```powershell
.\.venv\Scripts\python.exe main.py --simplify-lan-password
```

双击 `lan-info.bat`，或运行以下命令，在主机桌面查看地址、用户名和密码。密码默认隐藏，可点击复制或显示：

```powershell
.\.venv\Scripts\python.exe main.py --lan-info
```

用户名为 `gift`。主机通过 `http://127.0.0.1:8765/` 或 `http://localhost:8765/` 访问免登录；通过局域网 IP 或域名访问时，仍需完成工作台的 HTTP Basic 访问验证。免登录同时核对真实连接来自主机回环地址，不信任转发头。当前模式使用 HTTP，仅用于可信局域网。

## 防火墙与启动

正常关闭原工作台和工具浏览器，再重新双击 `start.bat`。配置启用后监听 IPv4，并在每个请求中限制为所选子网及本机回环地址。

在管理员 PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\allow-lan.ps1 -Port 8765
```

脚本仅添加本工具端口的入站规则，限制到配置的主机 IP、所在网卡及所选子网；不改变网络类型，不开放其它端口，不设置公网转发。重复执行会更新同名的本工具规则。主机 IP 改变后需更新共享配置与防火墙规则。

同一局域网设备可访问 `http://192.168.1.100:8765/`。首次打开时，在浏览器的账号密码框中输入独立访问账号。主机应保持开机，并由已登录的 Windows 用户运行工作台。

## 域名解析

将域名解析到主机的局域网 IP；DNS 不包含端口，因此访问地址仍需带 `:8765`。

可以在路由器的内网 DNS 中添加该主机记录。使用 Cloudflare 管理解析时，对应的 A 记录需要设置为主机内网 IP，并选 **仅 DNS / DNS only**。DNS-only 会直接返回记录地址，参见 [Cloudflare 代理状态说明](https://developers.cloudflare.com/dns/proxy-status/)。不要为此服务创建公网端口映射或公网隧道。

如果域名已有其他用途，先核对现存记录，避免覆盖已有网站或子域名。当前服务不会修改 DNS、路由器、浏览器的安全设置或代理配置。域名尚未生效时，可先使用内网 IP 地址。

如果主机上的代理使用虚拟 DNS，可为工作台域名设置单独的内网 hosts 映射，并保留修改前的备份。主机 IP 变更时，需要同步更新 DNS、此映射、共享配置及防火墙规则；其它设备通过 DNS 访问，无需安装代理或浏览器驱动。

## 网络或 IP 变化提醒

启用局域网模式后，工作台启动时及运行期间约每 30 秒检查一次已连接的物理网卡，忽略代理、VPN 和虚拟网卡。首次地址匹配时将网卡、网络名称、网关、IP 与子网基线保存到本机 `data/lan_network_baseline.json`，跨程序重启保留。旧配置地址已不在当前网络时，即使尚无基线也会提醒。

发现网络或 IP 变化后，主机弹出桌面提醒，本机工作台显示持续提示和“打开 Cloudflare”入口。相同变化在当前运行期间只弹一次；探测异常不清除已发现的变化。此功能只提醒人工核对，不自动修改 DNS、hosts、共享配置或防火墙。

如果 IP 变化，请按顺序处理：

1. 在 Cloudflare 核对工作台域名的 A 记录，设为用于共享的当前内网 IP，保持“仅 DNS”。
2. 用新的 IP 和子网重新执行 `main.py --enable-lan ...`，正常重启工作台。
3. 管理员重新执行 `allow-lan.ps1` 更新本工具规则；主机存在该域名的 hosts 映射时同步更新。

网络切换但 IP 不变时，核对 DNS 仍正确即可在本机提示上点击“已核对”，保存新网络基线。共享 IP/子网尚不匹配时不能忽略提醒。断网或探测失败也会在本机页面说明。其他设备不提供网络状态或核对接口。

## 访问日志

工作台把每个请求的最少信息追加到 `data/frontend_access.log`，每次启动还会写一行 `START`，用于确认运行中的进程加载了哪份 IP、子网和域名：

```text
2026-10-26T12:40:00+08:00 START port=8765 lan=on ip=192.168.1.100 subnet=192.168.1.0/24 domain=gifts.example.com
2026-10-26T12:41:02+08:00 403 GET /api/config gifts.example.com:8765 192.168.1.0/24
2026-10-26T12:41:05+08:00 200 GET /api/health 127.0.0.1:8765 loopback
```

只记录状态码、方法、不含查询参数的路径、Host 和客户端网段（如 `192.168.1.0/24`，回环记为 `loopback`）。不记录 Cookie、Authorization、请求体或访问密码；成功的状态轮询（`/api/registrations/status`、`/api/network/status`）不写入，避免刷掉有用的 401/403。文件超过 512 KB 轮转为 `frontend_access.log.1`，只保留一份备份。修改配置后需要重启工作台，`START` 行才会显示新值。

其他设备打不开时，在主机执行 `Get-Content data\frontend_access.log -Tail 20` 对照：

| 日志 | 含义 | 处理 |
| --- | --- | --- |
| `403 ... 192.168.1.0/24` | Host 或客户端子网不在当前共享配置内 | 用当前 IP/子网重新执行 `--enable-lan` 并重启工作台 |
| `401 ...` | 地址和子网已允许，缺访问密码 | 输入用户名 `gift` 与 `lan-info.bat` 显示的密码 |
| 没有任何新行 | 请求未到达工作台 | 检查防火墙规则、客户端是否在同一子网、主机是否在运行 |

日志只用于本机排错，位于已排除的 `data/` 目录，不要上传或发送给他人。

## 多设备使用

- 草稿和状态共享。其他窗口或设备保存后，旧版本写入返回冲突，不覆盖新数据；应先复制自己的编辑内容，再刷新。
- 不同设备点击相同业务，继续复用同一持久化任务；不会因为设备不同而再次提交。
- Selenium 浏览器、平台账号和加密会话都留在主机。平台登录、验证码及扫码需在主机打开 `login.bat` 维护；远端页面上的平台登录按钮会禁用。
- HTTP 页面中浏览器可能限制“读取剪贴板”按钮，仍可选中起始单元格后按 Ctrl+V 粘贴 Excel 内容。
- 主机需要通过 `http://127.0.0.1:8765/` 使用页面上的平台登录按钮；使用域名或内网 IP 时该按钮由主机维护。

## 关闭共享

```powershell
.\.venv\Scripts\python.exe main.py --disable-lan
powershell -ExecutionPolicy Bypass -File .\allow-lan.ps1 -Port 8765 -Disable
```

正常重启工作台后恢复仅本机访问。不会删除草稿、平台会话、访问密码或任务防重记录。

## 验证范围

网络单元测试使用临时配置及合成凭据，覆盖未认证访问、错误域名、子网限制、跨站写请求、共享版本冲突和重复任务复用。两套隔离 Chrome 验收共享工作台与远端按钮状态，业务使用显式替身；这些测试不会提交真实订单。真实局域网设备连通与 DNS 是否生效需单独核验。
