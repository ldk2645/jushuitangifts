# v1.2.0 启动修复与主机取消排队

## 启动故障

排查时旧工作台收到关闭请求，先关闭了 HTTP 监听，但后台仍在串行处理已接收订单并持有任务目录锁。再次双击会启动另一个无控制台 Python 进程，因无法取得锁而退出，界面没有显示原因。

`start.bat` 现在使用可见启动窗口：直连回环健康检查，已有服务就打开；旧服务正在结束时等待其释放锁，再自动启动。启动错误显示安全提示，不输出密码、会话或原始异常内容。关闭等待窗口不终止工作台。正常关闭期间保留进度页面，停止接收新登记，待队列结束后关闭浏览器、监听并释放锁；`stop.ps1` 超时只提示，不再强制结束进程。

## 取消排队

- 仅主机回环访问可操作。工具栏“修改所选状态”旁新增“取消所选排队”，每行“等待执行”旁新增“取消”，确认弹窗沿用现有样式。状态筛选新增“已取消”，自动列宽包含行内操作按钮。
- 后端核对 CSRF、草稿 revision、行内容和任务身份，防止旧页面取消后续新任务。取消与工作线程领取使用同一把锁；领取在平台调用前持久化。只取消未领取且明确未提交的排队项，同订单其它排队副本一并取消。
- 正在查询、提交、复查的任务继续完成。若确认期间状态已变化，返回未取消的行数；不会中断提交，不会自动重提。工作台正常关闭等待期间仍允许主机取消排队。
- 草稿、原快照、取消事件及执行身份保留。取消不会伪装成失败或成功，不安排失败后只读复核，也不进入成功/失败 Excel 日志。
- 刷新或重启不恢复执行。用户再次明确“开始登记”时，未执行的取消任务创建新快照；旧成功、失败和不确定提交记录继续参与按订单防重。失败重登被取消后仍使用原失败资格，并须主机重新请求及平台独立核查。人工成功继续排除。

## 验证与范围

完整隔离回归 528 项通过。首轮全套曾在关闭接口的无 Token 测试遇到一次 Windows 本地连接中止（10053）；该组单独复查及随后全套重跑均通过，未复现。

新增 9 项取消测试覆盖批次重复排队、领取竞态、失效页面、重启、历史保留、原失败防重、明确恢复、主机/CSRF/revision 校验以及关闭期间取消。使用临时任务目录与合成平台替身，不修改真实任务。

`smoke_queue_cancellation.py` 通过：临时 Chrome 和本地工作台验证逐单、所选取消、状态筛选、局域网隐藏入口、按钮列宽、关闭提示及关闭期间取消，只有原本已开始的合成订单完成。`smoke_launcher.py` 使用临时项目执行实际 BAT 分支，并核对 Tk 等待、错误及就绪提示。

本机真实工作台的 HTTP 健康检查已恢复正常。上述 Selenium 为隔离工作台验收，不代表真实班牛或聚水潭提交验收；本次未为测试提交或取消任何真实订单。改地址继续禁用。真实草稿、账号、会话、分组与历史保留，未同步 U 盘、未提交或推送 GitHub。

完成后确认没有排队或执行中订单，通过正常关闭接口及 `start.bat` 重启加载新代码；新进程健康检查、主机入口及取消接口的空选择校验通过（返回 400，未取消任何订单）。已有页面刷新后使用新功能。
