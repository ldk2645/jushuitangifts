# 2026-11-12 工作表启动载入优化

- HTTP 服务直接绑定配置地址，保留 Windows 独占端口保护，取消未使用的反向 DNS 查询，避免局域网 DNS 响应拖慢启动。
- 首屏并行请求配置和草稿。状态接口只返回当前草稿行，空表不扫描历史任务；草稿版本与状态来自同一次加锁读取，网络发送在释放锁后进行。
- 旧草稿已能按当前目录确认，或没有选中商品时，不再遍历全部任务历史。需要旧名称依据时只寻找目标任务，找到全部依据即停止扫描。
- 本地旧版队列补充状态缓存；历史任务文件新增、修改或删除时重新构建，返回结果独立复制。GitHub main 沿用其已有增量存储及状态缓存。
- 同时合入[内部订单号复核修复](2026-11-12-review-internal-order.md)，覆盖串行和独立核验浏览器。

本机测量：局域网端口初始化由约 1.261 秒降至 0.0004 秒；541 个任务 JSON 的状态读取原约 0.273 秒，缓存后的后续读取约 0.0132 秒。这些是单项测量，不代表整个启动耗时；冷读仍需解析历史，磁盘和机器负载会影响结果。空草稿直接跳过历史状态读取。

`tests/test_startup_loading.py` 覆盖无 DNS 启动、端口独占、空表跳过历史、当前行过滤、旧草稿确认及缓存失效。`tests/smoke_startup_loading.py` 用真实隔离 Chrome 和本地合成页面验证配置与草稿并发加载、空表和 1000 行首屏；不访问业务平台。

GitHub 更新基于 main 的 `45e3eba`，保留独立核验、任务日志及跨日导出功能。正常结束任务并重启工作台后加载本地修改。
