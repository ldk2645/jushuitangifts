# v1.2.0：订单与礼品组合判定（2026-11-02）

本次按用户确认，将任务身份从单独订单号调整为“订单号＋整组礼品编码”。同一订单的 A+B 与 B+A 是同一任务，A+B 与 A+C 是不同任务；名称、分组和行号不参与判定。不同组合可以包含重叠礼品。这取代此前版本说明中的“改变礼品也按同订单阻止”规则。

## 任务与历史

- 普通开始、历史结果复用、失败重登候选、行内重登、人工成功标记、延迟只读复核、取消排队和表格重复提示使用相同组合边界。相同组合的成功、失败和不确定提交继续防重；失败与不确定提交不会自动重提，每次任务仍最多提交一次。
- 旧快照、business_key、执行身份和审计不重写。旧人工标记从原签名/历史快照解析所属组合，仍对该组合生效，不扩散到同订单的其它礼品。旧记录缺少编码时继续保守拦截，不通过名称猜测。
- 旧版仅因同订单其它礼品而跳过的未执行行，在用户明确点击开始时创建新快照；原跳过记录保留。重启、刷新不会自动恢复执行。
- 取消只作用于所选组合及其重复排队副本；同订单其它组合继续排队。原失败重登被取消后，仍须主机明确重登和独立核查。
- 主机重登保留聚水潭原基线不变检查；班牛已有其它任务时，通过现有 Selenium 详情提取器逐项核对订单、任务身份及商家编码。已有相同组合、编码不完整、列表变化或读取异常时停止；其它组合可继续。提交前再次核对，未新增平台选择器。

## 礼品目录与分组

商品编码唯一，按字符串精确比较，保留前导零、大小写和标点。名称和别名可以重复；新增相同编码仍拒绝，不覆盖已有商品。前端完整编码优先匹配，同名文本有歧义时要求选择编码，已勾选编码不再反推成未匹配。

一个编码可属于多个分组。管理界面默认“加入分组（保留原分组）”，另支持移出所选分组和明确替换全部归属。分组保存不修改礼品目录、真实草稿或历史任务。

## 验证范围

完整隔离回归 540 项通过。Python Selenium 本地验收覆盖同名新增、精确编码粘贴、重复提示、按礼品重登和多分组持久化，以及生产班牛详情提取器对合成 HTML 的编码核对。原工作台 UI 和本地班牛卡住表单恢复的 Selenium 回归也通过。单元测试覆盖整组排序防重、允许部分重叠的新组合、跨重启防重、旧跳过快照兼容、缺少编码的保守阻止、人工结论归属、不同组合独立失败复核、取消范围及提交前再次核查。

本轮未向真实班牛/聚水潭提交订单，也未为验收修改真实礼品目录、分组、草稿或任务历史。隔离验收不等于真实平台整单提交通过。改地址继续禁用。上传仅包含本项目源码、脚本、测试及维护文档；订单 Excel、对账目录、本机配置、会话、凭据和运行数据不上传。
