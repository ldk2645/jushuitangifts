## 修复

- 在隔离 Chrome 复现了关闭当前标签、仍有存活标签时的失效引用：原判断只读取 `window_handles`，误认为当前页面可用。现在还检查当前句柄；只有一个存活标签时在下一次取得业务页时恢复，多标签歧义则保留窗口并提示主机确认。中断任务不会重放。
- 原先异常处理中的二次登录检查也可能抛错，从而覆盖最初失败阶段和提交边界。现在保留主异常、步骤和单次提交判断；二次认证失败只增加安全提示，不输出底层原始错误。
- 取得班牛业务页面失败、尚未调用提交适配器时，明确标记未提交；已经尝试点击提交后的失败始终保留不确定状态。旧历史不重新分类，不重置防重记录。
- 日志无法区分本单当时是人工关闭、浏览器退出还是会话失效，不能断言历史触发原因已完全复现；本轮修复的是可以复现和由代码确认的处理缺陷。

## 3 分钟只读复核

新失败任务在失败后 180 秒到期；队列忙时等待空闲。旧版已安排的 10 分钟期限在读取与调度时换算成 3 分钟，不重写原始历史。已领取、已中断或已完成复核的任务不会重新领取；即使旧备份缺少领取文件，已有复核结果也阻止重跑。缺少调度信息的历史失败不会被额外安排。

复核只读取聚水潭，仍须基线、提交依据及新增礼品/数量吻合才能自动成功，绝不因此再次提交班牛。人工成功排除重登等现有规则保持不变。

## 局域网更新脚本修复

同日另行复现 `update-lan.bat` 在网络配置步骤提前失败：原 `Get-NetIPConfiguration` 全量汇总查询超过 12 秒探测上限，异常被替换为笼统错误。这段探测逻辑在此前版本中已存在，不能归因于本次订单流程修改。

现改为先筛选启用的物理网卡，再读取对应接口的 IPv4 地址、网关和网络名称；整体探测上限 25 秒，继续排除虚拟网卡和非私网地址。超时、网卡查询失败及配置读写失败分别提示。BAT 区分网络配置与防火墙两步，第一步失败不执行防火墙脚本。新增 `update-lan.bat --check` 只读诊断，保留防火墙脚本依赖的 `lan_setup --check` JSON 接口。

网络相关回归测试 64 项通过，包含临时目录下的真实 BAT 分支执行（使用替身配置模块与替身防火墙脚本）。本机真实 `update-lan.bat --check` 通过，工作台本机/内网 IP 的 HTTP 及原访问密码校验通过。这些结果不代表其他局域网设备已连通。按本轮用户选择，真实防火墙、DNS 和 hosts 未修改；普通更新脚本的真实防火墙写入未执行。脚本修复立即可用，运行中的网络变化监测需正常重启工作台后加载新代码。
