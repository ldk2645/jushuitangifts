# v1.2.0（2026-10-28）

当前任务判定及礼品目录规则见 [2026-11-02 订单与礼品组合说明](v1.2.0-task-gifts.md)：按订单号＋整组编码防重，同名不同编码可新增，单个礼品支持多个分组。此规则取代下文较早的仅按订单号防重描述。

本版本直接修改现有项目，保留原有未提交改动。按用户后续确认，继续仅支持原地址礼赠，改地址接入延后。

## 功能与修复

1. 区域粘贴支持非整倍数自动填充。行列分别取选区和来源的较大尺寸，循环填满；来源较大时从左上角扩展。保留字符串编号、空单元格、撤销、整次校验及筛选隐藏行保护；状态列不接受粘贴。
2. IP 提醒增加删除按钮。当前浏览器隐藏本次提醒，刷新和轮询不重复显示，新的变化仍提醒。网络恢复后清除隐藏；不改变网络配置或把未核对网络标为正常。
3. 修复同名不同编码礼品勾选后被反向解析成未匹配、刷新时失去选择的问题。内部复制保留编码；纯文本同名歧义要求明确选择编码。没有更改现有礼品目录或分组。
4. 班牛业务页固定 1440×900 CSS 视口、页面缩放 1。保留已观察的新建控件定位、唯一性、加载/遮挡等待和原生单次点击；新增按钮缺失的专门提示。
5. 主机可给所选已结束订单添加人工成功、人工失败、待核查标记或恢复自动显示。人工标记独立持久化审计、独立状态筛选，绑定原草稿及执行时间，保留真实核验结果与重登资格。人工成功不伪装为平台成功，带标记草稿不自动归档删除。
6. 主机一键核查并重登本次所有失败订单，逐项返回接收或拦截原因。只创建独立新任务并逐单核查，不删除旧历史、不重置尝试标记、不追逐新失败。新增删除全部/所选草稿入口，先备份再删除，支持当前页面撤销；任务历史、防重和日志保留。

主机入口：`http://127.0.0.1:8765/` → 展开“概况与管理”。批量重登位于失败重登对话框；便携版端口仍为 8766。远程设备不能通过伪造转发头取得主机权限。

## 业务约束与数据兼容

- 每个任务班牛提交动作最多尝试一次。普通登记继续按订单号防重，复制、改礼品、删草稿再添加、手动改显示状态或重启均不恢复提交资格。
- 批量重登复用单条重登的资格、基线及班牛任务检查。已提交、提交超时、核验失败或证据不充分的订单保守拦截；各项失败不触发自动再次提交。
- 拉单最多等 60 秒；回执最多 24 轮、间隔 5 秒，另计页面加载。无效/旧回传号只读等待同一任务；业务不符和明确同步失败仍立即停止。
- 新文件 `data/manual_status.json` 保存人工标记和审计。完整删除前草稿备份位于 `data/draft_archive/`。继续保留全部 `data/`、本机账号与共享配置、会话、浏览器配置、礼品目录和分组；不把这些复制进源码或 Git。
- 当前磁盘目录有 38 项，历史核对文档记载的是当时的 37 项；以用户当前文件为准，本次未回滚或补猜目录。
- 便携构建脚本使用项目版本号，并携带人工标记审计。未运行构建、未覆盖 `E:\gifts`，其既有 runtime、Chrome、驱动和数据保持原状。

原有“新建按钮识别不到”的确切触发条件未复现，不能宣称已经证实是浏览器缩放导致。固定视口、现有选择器与空白新建路径已验证；实际业务整单登记、批量失败重登以及 U 盘环境尚未做真实平台提交验收。聚水潭逻辑未变，本轮仅通过隔离回归。模拟测试不代表真实平台业务验证通过。

改地址相关限制完整保留，后续需重新核对班牛地址字段/回执及聚水潭本次新增单据地址证据，再接入；本次未授权也未执行真实改地址提交。

正常退出当前工作台和登录助手，再用原入口启动并刷新页面可加载 1.2.0。没有重置项目、提交或推送 GitHub。
