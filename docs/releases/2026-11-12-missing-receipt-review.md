# 2026-11-12 缺失班牛回执的延迟复核

修复已点击提交但未取得班牛回执时，工作台一直显示失败的问题。失败后 180 秒进入只读复核，先补读班牛已保存任务，再用回执内部订单号核对聚水潭同一线上订单的新增记录；全部匹配后自动更新成功并保存回执、班牛任务编号与内部订单号。

- 新登记在点击返回后保存班牛提交前任务编号列表，补读时仅接受唯一新增任务。仍逐项核对订单、礼品编码、名称、数量、金额、补发类型和同步状态。
- 班牛订单号列可配置为外链，点击后会新开标签页，导致旧代码等不到任务详情。现在按任务编号定位普通“创建时间”单元格打开详情，并先滚动避开固定列遮挡；仍只执行一次原生点击。
- 旧记录须有已点击提交的标记、完整聚水潭基线和有效提交/失败时间。仅接受该时间段（两端各容差 120 秒）内的唯一班牛任务，再进行同样的完整核验；缺少证据、时间偏差过大、多任务或单号不符均保留待核查。
- 串行队列和独立核验通道均支持补读。独立通道使用单独的班牛浏览器配置，仅恢复已有会话，不登录、保存会话或调用登记方法。
- 未提交和明确拒绝的回执不能通过补读改写为成功。复核不新增或重提班牛登记；已完成的历史复核不批量重放。

验证包含针对性的 180 秒调度、两种通道、状态持久化、重启、歧义拒绝与只读浏览器测试。真实订单核查仅使用现有任务和登录配置，不执行真实登记。Cookie、订单记录及本机核查产物不纳入 Git。

2026-11-13 已通过现有平台配置只读核对工作台当前三条失败记录：三条均取得成功回执，内部单号均在对应聚水潭结果中出现且不在提交前基线中。备份原记录后，经修复后的复核逻辑持久化为成功，没有新建或重复登记订单。
