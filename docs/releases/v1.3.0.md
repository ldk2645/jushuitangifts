# v1.3.0 发布说明

## 功能与兼容

工作台已删除改地址列、圆点、编辑区域及相关入口，保留订单号、礼品、状态三列；状态列为 C。新版请求与任务快照不携带收件字段，原地址请求的 recipient 为 None。旧 True 草稿明确显示“旧草稿不支持”且拒绝执行；用户核实原意后自行处理，不自动转为原地址。旧四/七列复制的 False 行丢弃隐藏信息，True 行整次拒绝。历史文件和必要兼容结构保留，不清洗生产历史。

“礼品分组”位于自动列宽旁，与礼品选择框使用同一范围。偏好只存在当前浏览器 localStorage，各设备互不干扰；不改共享分组文件。已确认行保存编码与服务器生成的 gift_selection，包括每个编码的来源、时间及最近 100 次选择事件。切组、改名、改归属均不重新解释既有行。新增/改选必须带当前 scope 和版本，后端核对新增编码；伪造旧快照或复制新行不能继承组外权限。空组、删除组、配置版本变化会暂停新匹配，不回退全目录。跨组须明确切换后再新增，移除既有礼品须明确操作。

task_key 继续为订单号加排序去重后的整组编码，不加入名称、别名、分组或行 ID。行状态签名另保留行 ID、改地址请求和未匹配内容；展示名称/隐藏收件字段不影响状态。旧人工签名通过原任务快照解析；人工成功、待核查、真实失败及不确定提交仍受原防重约束。旧有编码行只在内存中按明确名称/别名匹配或同身份历史快照恢复确认依据；无编码或有歧义的旧文本保留待重新选择并阻止执行，不后台猜测。

## 状态核验与目录维护

聚水潭新增单据缺少数量、班牛回执缺少本次任务关联凭证时，继续保留待核查。后台只读复核使用同一任务的有效回执，前端忽略早于当前页面状态的轮询响应。

目录维护 CLI 支持离线预览、批准、应用与恢复。真实平台商品查询适配尚未接入。详见 [目录维护协议](../catalog-harness.md)。

## 升级

停止工作台并等待队列排空，再备份当前程序和完整 data、config。升级时保留最新任务记录、草稿、人工标记、登录环境和本地目录配置。重新启动后核对版本、草稿和状态。

## 保留新版提交记录的回滚

`tools/prepare_v120_rollback.py --source <正常停机后的最新data> --out <全新独立目录>` 只复制、生成清单，不部署、不覆盖源。它保留全部文件、执行身份、提交标记、回执、复核、任务键和人工事件，仅在副本中补充 v1.2.0 所需缺省字段；按最新 display_updated_at 对齐旧人工签名，并保留 v130_signature 原值。源文件在复制前后哈希必须一致；存在运行标记、链接、目标已有文件或目标为生产/U 盘均拒绝。

先以停机且队列已排空为操作前提，工具的运行标记/摘要检查不能替代正常停机。生成后用 v1.2.0 在另一个隔离目录验证全量数量、所有成功/失败/不确定提交、防重及人工 pending；处理目录更名引起的旧版展示差异，不能因界面空白清除任务。验证通过后才将最新兼容副本用于回滚切换。旧地址 True 请求依然拒绝，旧版不具备 v1.3 的分组范围能力；这一差异必须告知使用者。绝不可直接拿上线前 data 覆盖新数据。
