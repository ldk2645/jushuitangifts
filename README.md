# 礼赠自动登记工具

Version 1.3.0（2026-11-04）。面向 Windows 的 Python + Selenium 工具，通过本地表格工作台管理订单与礼品，在聚水潭查询订单、向班牛登记，再回聚水潭核对新增记录。

**本版本仅支持原地址礼赠。** 工作台仅显示订单号、礼品及状态三列。旧改地址草稿标记为不支持并阻止执行；不会静默改成原地址任务，也不显示旧收件信息。

## v1.3.0 更新

- 商品编码按完整字符串精确匹配，保留大小写、前导零和标点；缺位、错位或不完整编码保持未匹配，名称和别名仍支持匹配。搜索框、公式栏和粘贴遵循相同规则。
- Excel 式下拉填充：拖动选区右下角绿色填充柄，单行重复、多行循环；Ctrl+D 将首行填充至选区下方；双击填充至相邻列连续内容末行。支持自动滚动、筛选、扩展新行、Esc 取消及 Ctrl+Z 撤销。订单号和编码按原文复制，不递增；分组限制继续生效。

- 工具栏“礼品分组”只约束当前浏览器后续输入，各设备独立保存偏好。已有行的已选编码保持不变，组外编码、失效分组和过期版本均不能自动回退匹配。新增或改选还须通过后端范围校验，并保存选择来源快照。
- 状态关联排除展示名称与隐藏收件字段，保留任务身份、改地址标记和未匹配内容；乱序轮询不能覆盖较新状态。新增单据缺数量、缺有效回执关联时继续保留失败/待核查，不能用点击或新增差异推断成功。
- 交付 [目录维护 CLI 与协议](docs/catalog-harness.md)、[DeepSeek 受限任务提示词](docs/deepseek-catalog-prompt.md)。默认预览，明确批准计划后才可应用；商品页面查询尚未接入，返回 blocked，不生成平台名称证据。
- 用户于 2026-11-04 明确授权将 v1.3.0 启用到原 NL 目录，见 [本次更新说明](docs/releases/v1.3.0-enable.md)。之前的状态修复证据、隔离验收及保留最新防重历史的回滚方案见 [v1.3.0 交付说明](docs/releases/v1.3.0.md)。

- 当前任务身份为“订单号＋整组礼品编码”：A+B 与 B+A 相同，A+B 与 A+C 不同；名称与分组不参与判定。同名不同编码可以新增，单个礼品可加入多个分组并保留原归属。详见 [任务身份与礼品目录说明](docs/releases/v1.2.0-task-gifts.md)。

- 区域粘贴支持非整倍数自动填充：从选区左上角开始，行、列各取“来源尺寸与选区尺寸的较大值”，循环来源直到填满。例如 2 行内容粘贴到 5 行选区，得到第 1、2、1、2、1 行。单格起点自动扩展，筛选时只修改可见行；状态列仍不可粘贴。布尔值或长度校验不通过时整次粘贴不落盘，可用 Ctrl+Z 撤销成功粘贴。
- 已选礼品按商品编码保留，修复同名不同编码的礼品勾选后出现“未匹配”、刷新丢失选择的问题。工作台内部区域复制保留编码；外部纯文本只含同名名称时仍需人工选择编码，不能猜商品。
- IP 提醒增加“删除提醒”：当前浏览器记住本次隐藏，轮询和刷新不会重新出现；新的变化仍提醒，网络恢复后重置隐藏。此按钮仅隐藏提示，不更改 IP、DNS、防火墙或网络核对基线。
- 班牛进入礼赠列表前固定工具浏览器的 1440×900 CSS 视口和 1 倍页面缩放；保留唯一控件、遮挡和原生单次点击检查。“新建”按钮缺失时给出专门错误。真实页面已验证可打开、关闭空白表单，未提交订单；原问题的确切触发条件尚未复现。
- 根据失败记录追加修复班牛横向虚拟表格缺列引起的“列表未就绪”：先完成订单筛选，再滚动读取同一快照中的订单号与创建时间；滚动后的任务/礼品行在首次点击前重新按身份查找。重登核查失败不再误报为聚水潭首次查询失败。真实平台只读筛选及已有任务详情已核对，详见[失败排查说明](docs/releases/v1.2.0-failure-fix.md)。
- 主机工具栏中“修改所选状态”紧邻“重新登记”，删除草稿仍位于“概况与管理”；重登列表仅包含当前已保存表格中的失败订单，人工成功及人工待核查排除。详见下方主机管理及 [v1.2.0 版本说明](docs/releases/v1.2.0.md)。
- 双击启动会显示等待和错误原因；关闭时保留查看进度的页面，完成任务后退出，不再强制结束在途进程。主机新增“取消所选排队”及每行“等待执行”旁的取消按钮，详见 [启动与排队取消说明](docs/releases/v1.2.0-2026-11-01.md)。

## 安装

需要 Windows、Python 3.12（含 tkinter）和已安装的 Chrome。在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
.\.venv\Scripts\python.exe main.py --version
```

安装脚本创建或复用 `.venv`，并安装 `requirements.txt` 中的依赖。首次启动浏览器时，Selenium Manager 需要联网获取与 Chrome 匹配的驱动。前端无需 Node.js 或构建步骤。

## 使用

1. 双击 `start.bat`，启动窗口就绪后自动打开本地工作台 `http://127.0.0.1:8765/`。已有工作台正常运行时直接打开；旧进程正在结束任务时显示等待，退出后自动启动。关闭启动窗口仅停止等待，不结束登记任务；启动失败会显示原因。
2. 点击“平台登录”，或双击 `login.bat`。在工具打开的两个独立 Chrome 窗口中完成登录；验证码、扫码和二次验证由人工完成。
3. 登录成功后点击对应平台的“我已登录，确认并保存”，再点击“保存并关闭浏览器”，释放登录配置。
4. 选择本设备需要的礼品分组，填写订单号并选择该订单的全部礼品；跨组新增礼品须先明确切换分组。
5. 点击“star 开始登记”。工具保存任务快照，按订单逐条串行执行；鼠标停在状态上可查看结果或失败原因。
6. 结束时双击 `stop.bat`（默认端口 8765；其他端口用 `stop.bat 8766`）。它请求正常退出，等待已接收任务、关闭业务浏览器并释放任务目录。等待期间页面可查看进度，主机仍可取消排队；保存、新登记和其它管理操作暂停。超时只提示等待，不强制结束进程。登录助手请在其窗口中点击“保存并关闭浏览器”。

主机可点击每行“等待执行”旁的“取消”，或选中多行后点击“取消所选排队”。确认后只取消尚未领取的所选任务，同订单及同礼品组合在其它批次中的排队副本一并取消，其它组合继续排队；查询、登记、复查中的任务继续完成。显示“已取消”并保留草稿、原任务及取消记录，不产生失败复核或成功日志。需要恢复时，明确点击“开始登记”会为未执行的取消任务创建新快照；原成功、失败和不确定提交记录仍按订单及礼品组合防重。取消的失败重登仍需从主机重登入口重新核查，同组合的人工成功仍排除。

工作台支持多行新增、Excel 多行粘贴、礼品多选与组内模糊匹配、自动保存、撤销和列宽调整。订单号和商品编码按字符串处理，保留前导零及长编号。输入内容保存在本机草稿中，刷新后可继续编辑。

礼品目录位于 `config/gifts.json`，商品编码就是唯一礼品 ID。支持点击“新增礼赠”，填写编码、名称和可选别名；名称和别名允许重复，重复编码拒绝且不覆盖旧项。编码按原字符串精确比较（保留前导零、大小写和标点）。粘贴精确编码优先匹配；同名文字对应多个编码时保留待匹配，需人工选择，已选编码不会被名称反向覆盖。

工作台默认只监听 `127.0.0.1`；可配置带独立访问密码的[局域网共享模式](docs/lan.md)。启动程序、保存草稿及轮询状态不会自行登记。若登录助手仍占用配置，开始操作会提示先关闭助手，本次不创建业务任务；关闭后需再次明确点击开始。

启用共享后，主机通过 `127.0.0.1` 或 `localhost` 仍免登录；通过局域网 IP、域名访问继续使用独立访问密码。

局域网新密码使用六位数字，仍在本机加密保存；旧长密码可通过 `main.py --simplify-lan-password` 明确更换后重启。网络或 IP 变化时，工具在主机弹出提醒，并在本机工作台提示去 Cloudflare 核对 DNS 和同步本机共享配置；详见[局域网说明](docs/lan.md)。其他设备打不开时先看 `data/frontend_access.log`：只记录状态码、方法、无查询参数的路径、Host 与客户端网段，不记录 Cookie、密码或请求体。

多订单和后续批次复用同一组平台浏览器。订单页或礼赠列表已就绪时，直接更新订单号并查询，减少整页重复加载；详情页、其它入口或页面未就绪时才重新进入已核对的列表。每次查询仍须确认本次刷新，原订单基线、回执和成功结果不会跨订单复用。浏览器保留到正常关闭工作台，不按订单反复开关。

如果手动关闭了平台浏览器，下次获取业务页面时会先确认旧会话已关闭、清理旧驱动，再复用原登录配置打开新浏览器，并重建页面适配器。连接超时等无法确认关闭的情况不会另开浏览器；提交途中关闭窗口仍按失败处理，不重放提交。已失败订单不会因此自动恢复。

班牛同一带 `#` 的地址仍残留详情时，会刷新一次并等待列表恢复可交互。工具自己提交后卡住的表单，在下一单查询或主机重登核查前确认归属、订单、礼品及无人修改后，刷新一次再继续完整核查；人工或归属不明的编辑表单仍保留。关键按钮与回执入口先检查实际点击位置，避免透明加载层拦截。等待失败不会再次提交，状态详情会区分提交前失败与点击提交后的不确定结果。

填写失败后，会关闭本次自动创建、未触发提交且未被人工修改的表单，让后续独立订单继续。人工表单、内容异常的表单保留供核查。提交结果不确定的上一单始终保留失败历史和防重依据，即使为后续订单刷新了页面，也不会重新提交上一单。同编码的平台名称差异只通过已核对的明确映射兼容，不使用相似名称替代不同商品编码。

班牛拉单确认最长等待 60 秒，不重复回车。任务保存后的异步同步最多进行 24 轮只读回执核验，轮次间隔 5 秒（间隔总计最多 115 秒，另计页面加载时间）。回传单号尚无效或仍为旧号时，只等待同一新增任务更新，不把旧号作为成功依据。明确同步失败或业务信息不符立即停止；等待耗尽仍未确认成功则失败。筛选后表格仍未刷新时，最多刷新列表重查一次；已有编辑表单须先满足上述恢复条件。上述等待和重查均不会重新提交登记。

修改 Cloudflare DNS 或更换网络后，可双击 `update-lan.bat`：自动更新本机共享 IP/子网，弹出管理员授权后更新 8765 防火墙规则，保留域名及密码。IP 变化后需要正常重启工作台。详见 [局域网说明](docs/lan.md)。

只排查网络时运行 `update-lan.bat --check`，不会修改配置或防火墙。已修复物理网卡探测超时导致的更新失败，并分别显示网络配置与防火墙步骤的报错。

## U 盘便携副本

便携版包含独立 Python 3.12、Tk、Selenium，默认使用目标电脑安装的 Microsoft Edge，首次使用或 Edge 更新后联网匹配 EdgeDriver；目标 Windows 10/11 x64 无需安装 Python 依赖。双击便携目录的 `start.bat`，访问 `http://127.0.0.1:8766/`；`login.bat` 登录平台，`accounts.bat` 在目标电脑加密配置自动登录账号，`stop.bat` 正常关闭。盘符可变化，目录结构须完整。便携包内的“便携版使用说明.txt”说明数据与退出方式。

制作时保留当前草稿、礼品分组、完整防重复任务历史；不复制不能跨用户解密的登录凭据、浏览器用户配置和原电脑局域网设置。源电脑与便携版的后续数据各自保存，请固定使用一份进行同一业务，避免历史分叉。构建脚本 `tools/build_portable.py` 只向没有项目文件的新目录添加文件，默认不再打包 Chrome，要求源工作台已正常退出。

便携版共享不需要域名：在目标电脑运行 `lan-setup.bat` 选择实际网络，管理员运行 `allow-lan.bat`，重启工作台后，其他设备通过 `http://主机内网IP:8766/` 访问。`lan-info.bat` 显示地址与六位密码。完整步骤见 [无域名局域网说明](docs/portable-lan.md)。

2026-10-28 已通过 Selenium 重新核对全部 37 个礼品编码，更新 8 项名称，旧称保留为别名；见 [名称核对表](docs/catalog-name-review-2026-10-28.md)。同名的两个手表仍以不同商品编码区分。

## 自动登录与本机数据

便携版新增 `settings.bat`，在目标电脑配置两平台账号密码及各自的业务浏览器无头模式，统一保存到 `config/accounts.local.json`。密码使用 DPAPI 加密，默认浏览器可见；登录助手始终可见。保存后正常关闭并重启工作台生效。详见 [账号与浏览器配置](docs/portable-settings.md)。

工具优先复用各平台独立的 Chrome 配置，以及加密保存的 Cookie、localStorage 和 sessionStorage。会话过期后，若已配置账号，则在识别到官方 HTTPS 登录表单时尝试一次账号密码登录。验证码、二次验证、密码错误或结果不确定时提示人工处理，不反复发送密码。

自动登录账号由 `CredentialStore` 保存到本机 `config/accounts.local.json`。可在项目目录通过以下交互命令配置，密码输入不回显，也不写入命令历史：

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from gift_registry.config import SITES; from gift_registry.credentials import CredentialStore; store = CredentialStore(); [(print(site.name), store.save(site.key, input('Username: '), getpass('Password: '))) for site in SITES]; print('Saved locally.')"
```

用户名按文本保存，密码和会话快照使用当前 Windows 用户的 DPAPI 加密。账号配置及整个 `data/` 目录均排除在 Git 之外；GitHub 发布不包含账号、会话、用户草稿或任务记录。换电脑或 Windows 用户后需重新配置登录，不能直接解密旧快照。Chrome 配置由浏览器管理，其整个目录并非均由本项目 DPAPI 加密。

**升级前正常退出工作台和登录助手，备份并保留 `data/`、本机账号配置及自行维护的礼品目录。** 持久化防重记录及执行历史位于 `data/registration_jobs/`（包括 `execution_history/`）；删除或遗漏它们会丢失既往登记依据。同一订单及礼品组合不能靠复制新行、调整编码顺序或重启程序绕过历史结果；不同组合是新任务。

## 主机管理

在主机打开 `http://127.0.0.1:8765/` 或 `http://localhost:8765/`，工具栏提供重登与人工状态；展开“概况与管理”使用日志导出及草稿删除。局域网 IP 或域名入口不显示主机管理按钮，后端也会拒绝对应请求。

- 普通“开始登记”按去除首尾空格后的订单号＋排序去重后的整组礼品编码防重。同组合有成功或失败历史时，复制行、调整礼品顺序、跨批次或重启均不再提交；不同组合可成为新任务，旧成功不会被当作新组合的登记结果。
- 主机重登使用失败记录中保存的订单及礼品，保留原任务。点击“核查并重登”后创建一个独立任务，先重新查聚水潭基线和班牛任务列表；仅确定此前未提交、原有基线未变化（如已记录）、班牛无该订单及相同礼品组合的任务、其它旧任务编码均可核对时，才允许提交一次。已提交、超时不确定或历史证据不足的订单显示禁止原因，不能用此入口重提。相同失败记录的重复请求只复用同一个重登任务。
- “一键核查并重登当前可重登订单”只固定当前已保存表格中的可重登失败标识列表（包括筛选隐藏行，不包括已删除草稿和人工成功/待核查订单），逐单创建独立重登任务并串行核查；不确定提交和不符合资格的记录列出拦截原因。重复请求复用原任务，本批次产生的新失败不会自动继续重登。
- “修改所选状态”支持人工标记成功、人工标记失败、人工待核查，以及恢复自动结果显示。仅处理已结束且草稿内容未改动的订单；人工标记有独立筛选及审计，保存于 `data/manual_status.json`。不会改写平台执行结果、成功日志或重登资格，也不会把订单重置成可提交。后台更新时间和结果复用不再使人工标记失效。人工成功按订单及礼品组合持续保留（含复制行），直到主机明确更改或恢复自动显示，并由服务端排除重登；带人工标记的草稿不自动清理。
- “删除所选订单”仅删除当前可见选区对应草稿；“删除全部订单”包括筛选隐藏行。队列执行或复核期间禁止这两项管理删除；先在 `data/draft_archive/` 完整备份，成功后再删除草稿，可在当前页面撤销。任务记录、历史、日志及防重依据保留，重新添加订单仍防重。
- 今日日志按主机当天日期和实际完成时间统计，下载 `.xlsx`，包含“成功登记”和“失败登记”两个工作表。成功项含订单号及经新增核验确认的内部订单号；失败项含订单号及原因。重复点击和复制行不重复计数；重登前的失败及重登结果分别保留。订单号、内部订单号均为文本，不丢前导零和长数字精度。正在执行的任务结束后再导出，可获得完整结果。

## v1.1.1 分组、筛选与自动复核

- 礼品选择框支持分组筛选，初始提供“小米生态链”和“小米手机”，已有归属保留。主机可批量勾选礼品并选择多个分组；默认“加入分组”保留原归属，另可移出所选分组，或明确选择“设置为所选分组”替换归属（此模式选空表示恢复未分组）。配置保存在 `config/gift_groups.local.json`，升级时一起保留。
- 状态列下拉框可筛选成功、失败、待登记等状态。筛选只影响显示；复制、粘贴、删除作用于可见行，隐藏行保留。“开始登记”仍使用完整已保存草稿，并按订单号＋礼品组合跳过已有成功或失败记录。
- 北京时间每天 01:00，后台先导出上一日 Excel 到 `data/exports/gift-registration-YYYY-MM-DD.xlsx`，再清理当前表格中截至该时间已成功、且内容未被修改的行。失败行、未执行行和所有历史防重记录均保留。清理前的完整草稿备份在 `data/draft_archive/`；导出或备份失败时不清理。
- 新版本首次启用从下一个 01:00 开始；之后若主机关机或工作台关闭，重新启动后补做错过的日期。定时任务依赖工作台运行，正在登记或复核时会等待队列空闲。已保存且未编辑的前端会自动同步清理结果，有未保存编辑时提示冲突并保留当前输入。
- 本版本产生的原地址失败任务在失败 3 分钟后进入一次只读复核，与登记共用串行队列。仅当原始基线、本次提交依据和聚水潭新增礼品／数量全部吻合时转为成功；旧有相同礼品不能作为新增证据。不一致、无新增或查询异常时仍为失败，绝不再次提交班牛。缺少调度信息的升级前失败记录不批量自动复核；已领取复核但中断的任务不会在重启后重复执行。
- 自动复核后的日志仍归属原登记完成日期。若对应日期已自动导出，后台更新该 Excel；此前手动下载的文件需重新导出。成功行将在后续 01:00 清理。展开主机管理区可查看下次归档时间、导出目录和归档异常。

## 业务结果与限制

- 聚水潭先保存原订单与已有记录作为基线；班牛将全部礼品加入同一个任务，最多提交一次；提交后读取回执，再回聚水潭核对新增记录。
- 只有本次新增记录、订单号、礼品编码、数量及回执关联信息均一致，才返回“成功”。已有相同礼品、按钮点击成功或平台提示成功都不足以判定成功。
- 失败、超时和结果不确定均不自动重提。普通登记按订单号＋礼品组合跳过历史成功、失败；仅主机明确发起的重登任务可进入单独核查。
- 登录恢复只允许有界的只读重查，不重新填写失效的登记表单，也不重试礼赠提交。
- 页面适配针对已核对的聚水潭订单页和班牛礼赠工作表；平台页面、权限或字段变化时需要重新验证。主机重登不会放宽新增记录核验或不确定提交的保护。

详细规则见 [业务流程](docs/business-workflow.md)、[自动登录](docs/automatic-login.md) 和 [v1.2.0 版本说明](docs/releases/v1.2.0.md)。

## 2026-11-02 Chrome 离线便携版与升级指南

本次 U 盘发行使用 **Chrome for Testing 156.0.8078.80（Windows x64）＋相同版本 ChromeDriver**。浏览器来自 [Google 官方发布目录](https://googlechromelabs.github.io/chrome-for-testing/)，离线 ZIP 保存在便携目录的 `offline-packages/`，已解压到 `chrome/chrome-win64/`。这是免安装的完整浏览器包，不是修改系统默认浏览器的安装程序；解压后即可由工具启动。浏览器与驱动必须成对升级，不能仅替换其中一个。

### 两种运行方式

| 项目 | 原项目 | 本次 U 盘 Chrome 包 |
| --- | --- | --- |
| Python | `.venv/Scripts/python.exe` | `runtime/python.exe` |
| 入口 | 双击 `start.bat` | 双击便携目录 `start.bat` |
| 主机地址 | `http://127.0.0.1:8765/` | `http://127.0.0.1:8766/` |
| 浏览器 | 本机 Chrome | 包内固定版本 Chrome |
| 驱动 | Selenium Manager 匹配 | `drivers/chromedriver.exe` |
| 首次安装依赖 | 运行 `setup.ps1` | 已包含 Python、Tk、Selenium，无需安装 |

构建脚本不传 `--chrome` 时仍默认制作使用系统 Edge 的包；实际使用哪种浏览器以该副本 `portable.json` 为准。离线包只解决运行环境安装问题，聚水潭、班牛登录和订单操作仍须联网。

### 新电脑首次使用

1. 保留整个 `gifts` 目录结构。可改变 U 盘盘符，也可整体复制到本机硬盘；不要单独拖走 BAT 或 Python 文件。
2. 双击 `start.bat`，打开本机 8766 地址。首次迁移不要同时开启另一份工作台处理同一业务。
3. 双击 `settings.bat` 设置两平台账号和是否无头运行；密码由目标 Windows 用户的 DPAPI 加密。不能把原电脑密文当成可迁移账号。
4. 通过 `login.bat` 完成人工登录、扫码或验证码，确认并保存，然后关闭登录助手。配置占用时不能开始业务。
5. 检查礼品目录、分组、草稿和历史是否完整，再明确开始登记。更换浏览器不会清除历史防重。
6. 使用 `stop.bat` 正常退出，等待在途业务与浏览器结束，再拔出 U 盘。

### 其他设备访问

便携主机执行 `lan-setup.bat` 选择当前物理网卡，再运行 `allow-lan.bat` 并完成 Windows 管理员授权，正常重启。其他设备输入 `http://主机当前内网IP:8766/`，使用 `lan-info.bat` 显示的独立访问密码；主机使用回环地址进行重登、取消排队、人工状态和导出管理。没有域名也能共享。

如果使用域名，DNS 记录必须与当前主机 IP 一致，地址还需要正确端口。只显示 Bad Gateway 时，应结合主机访问日志区分请求未到达、代理问题与应用拒绝。不要通过关闭整个防火墙解决连接问题。详见 [局域网配置](docs/lan.md) 和 [便携版局域网步骤](docs/portable-lan.md)。

### 备份与升级顺序

1. 先正常退出旧工作台与登录助手，确保正在运行的任务已结束。
2. 备份完整 `data/`、`config/` 和 `portable.json`；特别保留 `registration_jobs/`、`execution_history/`、人工状态及草稿。不要通过删历史制造重登资格。
3. 代码更新覆盖程序文件时保留上述本机数据，禁止用空目录覆盖历史。构建脚本只接受没有项目文件的新目标，避免误覆盖。
4. 跨电脑重新配置账号、平台登录和局域网访问；不要复制源电脑的 Cookie、浏览器用户配置或不可解密的凭据。
5. 迁移后只固定使用一份业务数据。源项目和 U 盘不会自动同步，交替使用会使防重历史分叉。

### 常见现象

| 现象 | 检查与处理 |
| --- | --- |
| Chrome 无法启动或版本不匹配 | 检查 `portable.json` 的浏览器和驱动路径；两个文件必须为相同发布版本，保留完整 Chrome 解压目录 |
| 普通内网 HTTP 空表/加行失败 | 更新到本次局域网修复，并刷新客户端页面；已兼容非安全上下文的行 ID 生成 |
| 主机重启后提示连接已更新 | 页面保留未保存内容，确认提示本次未执行后再次点击；不自动重发业务请求 |
| 断线或请求超时 | 保留页面，恢复后核对最新结果；超时不代表服务器没有执行 |
| 多设备保存冲突 | 先复制保留自己的编辑，再载入最新草稿；不覆盖其他设备已保存的版本 |
| 已人工标记成功仍需核对平台 | 人工显示状态不改变平台证据和执行日志，不重置实际提交历史 |

本轮局域网修复通过 546 项单元回归和两套隔离 Selenium 验收；测试不等于真实平台提交通过，也不代替目标电脑及其他局域网设备的实测。详细变更见 [局域网修复说明](docs/releases/v1.2.0-lan-reliability.md)。浏览器二进制、离线 ZIP、运行数据和凭据仅保存在本地/U 盘，不上传 GitHub。
